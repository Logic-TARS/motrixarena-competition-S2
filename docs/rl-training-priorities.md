# RL 训练优先级建议

当前这套系统里，最需要强化学习的部分是**底层运动控制**，而不是一开始就把 RL 用在比赛策略上。

可以按三层来看。

## 1. 底层行走控制：最需要 RL

底层行走控制的任务是把速度命令：

```text
vx, vy, yaw_rate
```

转换成机器人关节动作，让 K1 能够稳定地前进、后退、横移、转向，并且不摔倒。

这一层非常适合用 RL，因为它具备典型的连续控制特征：

- 动作空间连续；
- 机器人动力学复杂；
- 足地接触多，接触状态变化快；
- 很难用手写规则覆盖所有姿态、速度和扰动情况。

目前也已经能看到这一层模型质量的重要性：默认的 `models/k1/model_20000_new.onnx` 表现不好，而 `models/k1/model_4700.pt` 能跑起来，说明底层 locomotion policy 的质量会直接决定整套系统能不能稳定工作。

这一层的训练目标应该是：

> 给定目标速度 `cmd_vel`，让机器人稳定跟踪速度，同时保持站立、降低能耗，并具备一定抗扰动能力。

## 2. 带球 / 推球控制：可能需要 RL，但可以先用规则调通

带球和推球控制关注的是机器人靠近球之后的行为，例如：

- 怎么把球往球门方向推；
- 怎么绕到球后面；
- 怎么避免把球推偏或踢偏；
- 怎么在球偏离目标方向后修正姿态。

这一层也可以使用 RL，因为它涉及机器人和球之间的接触，精确建模和手写规则都比较困难。

不过建议先用规则或 P 控制把基本流程跑通：

```text
追球 -> 对准球门方向 -> 慢速推球 -> 修正方向
```

等规则策略遇到明显瓶颈，比如推球方向不稳定、修正慢、接触后球经常失控，再考虑训练专门的 dribble / kick RL policy。

## 3. 比赛决策：暂时不急着 RL

比赛决策包括：

- 谁去追球；
- 谁负责防守；
- 什么时候射门；
- 什么时候回防；
- 球在不同区域时采用什么队形。

这一层前期可以先用规则策略实现，尤其是在 1v1 和 3v3 的早期阶段：

- 最近的人追球；
- 其他人站防守点；
- 靠近球门时推球或射门；
- 球在己方半场时优先解围。

直接用 RL 训练整场比赛策略会比较困难，因为：

- 奖励稀疏；
- 训练周期长；
- 多智能体协作会放大不稳定性；
- debug 成本高；
- 底层控制不稳时，高层策略很难学到有效行为。

所以当前阶段还不适合优先做整场比赛策略 RL。

## 推荐推进顺序

建议按下面的顺序推进：

1. 先用规则调通比赛策略；
2. 先用现有 `models/k1/model_4700.pt` 跑通 1v1 / 3v3；
3. 如果行走稳定性、速度跟踪或抗扰动能力不够，再训练底层 locomotion RL；
4. 如果带球规则达到瓶颈，再训练 dribble / kick RL；
5. 最后再考虑整队比赛策略 RL。

## 总结

一句话：

> RL 应该先用在“让机器人会走、能稳定移动、能稳定推球”这种连续动作层；比赛怎么赢，前期先靠规则策略。
